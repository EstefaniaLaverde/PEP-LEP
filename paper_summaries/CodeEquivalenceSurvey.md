# A Survey on Code Equivalence: Summary

**Source:** Horlemann, Mazumder, Schaller, Weger — "A Survey on Code Equivalence: The State-of-the-Art and Open Questions" (arXiv:2607.12870, July 2026)

## 1. Motivation

The code equivalence problem asks whether two linear codes are related by a distance-preserving map (a Hamming isometry). It has become a central hardness assumption in post-quantum cryptography, underpinning signature schemes such as LESS, PERK, SPECK, and VOLE-in-the-Head constructions. Despite a large and fragmented literature — spanning combinatorics, algebra, and graph theory — no unified picture of its hardness existed before this survey. Its goal is threefold: unify the problem variants, catalog known attacks and the regimes where they work, and lay out open questions.

## 2. Core Definitions

- **Linear code**: a k-dimensional subspace of F_q^n (an [n,k]_q code), generated by a k×n matrix G.
- **Dual code / hull**: C^⊥ is the orthogonal complement of C; the hull H(C) = C ∩ C^⊥ is the single most important structural invariant in the survey. Trivial hull (H(C)={0}) → LCD code; H(C)=C → self-orthogonal code. Random codes have trivial hull with high probability as n grows.
- **Isometry**: any Hamming-distance-preserving map on F_q^n is provably a monomial transformation — a permutation composed with nonzero coordinatewise scalars (Mn,q = (F_q*)^n ⋊ S_n).
- **Linear vs. permutation equivalence**: linear equivalence allows a full monomial map; permutation equivalence restricts to pure permutations (scalars fixed at 1).
- **Invariants**: length, dimension, minimum distance, weight enumerator, generalized weights, automorphism group, and (for permutation equivalence) the hull — all preserved under equivalence, and exploited by solvers.
- **Schur product / power codes**: the componentwise product of codewords, and its iterated version (power codes), give an algebraic handle on equivalence that low-weight-codeword search does not.

## 3. Problem Variants

| Problem | Allowed isometry | Notes |
|---|---|---|
| **PEP** (Permutation Equivalence) | σ ∈ S_n only | Special case of LEP with trivial scalar group |
| **LEP** (Linear Equivalence) | (d, σ) ∈ (F_q*)^n ⋊ S_n | Full monomial group |
| **LEP(U)** | (d, σ) ∈ U^n ⋊ S_n, U ≤ F_q* | Unifying template; U={1}→PEP, U={±1}→SPEP, U=F_q*→LEP |
| **SPEP** (Signed Permutation Equivalence) | signs ± only | Natural isometry group in the Lee metric |
| **PKP** (Permuted Kernel Problem) | σ ∈ S_n, subcode containment | Decision version is NP-hard (unlike the others) |

Note: for q=2, LEP collapses to PEP; for q=3, LEP collapses to SPEP. The LEP/PEP gap only opens up for q ≥ 4.

**Complexity class**: the decisional versions of LEP(U) lie in AM ∩ coAM — like graph isomorphism — suggesting they are *not* NP-hard (NP-hardness would collapse the polynomial hierarchy), yet no efficient general algorithm is known. PKP's decision version, by contrast, is proven NP-hard.

## 4. Known Reductions

- **LEP(U) → PEP** via the *closure* construction (Kronecker product blow-up): runs in poly(n, |U|) time, but for |U| > 2 the resulting code becomes self-orthogonal — landing exactly in PEP's hardest regime. Practical only for small |U| (e.g., SPEP → PEP, length ×2). For q=4 a Hermitian-inner-product variant works, but the underlying algebra shows this cannot generalize to larger q.
- **PEP → Graph Isomorphism**: for codes with *trivial hull*, a canonical adjacency-like matrix A(G) = G^T(GG^T)^-1 G reduces PEP (and SPEP) to (signed) graph isomorphism, inheriting Babai's quasi-polynomial GI algorithm (2^O(log(n)^c)). Fails when the hull is nontrivial.
- **Search-to-decision**: proven for PEP (an oracle deciding equivalence can be bootstrapped, coordinate by coordinate, into full recovery of σ). Open for LEP.
- **SPEP → Lattice Isomorphism Problem (LIP)**: via Construction-A lattices, efficient (poly(n, log p)) but restricted to prime fields and codes with large minimum distance (> p²/... +1). A less efficient LEP → LIP path exists (poly(n,p)) via intermediate constructions.
- **PEP → LEP, PEP → SPEP**: poly(n, log q).
- **LEP → Matrix Code Equivalence (MCE)**: poly(n), by embedding the diagonal scaling vector into a diagonal matrix — LEP becomes a structured special case of the broader "AMB-equivalence" of matrix codes.
- **PEP/LEP → automorphism-group-order problem**: probabilistic reduction.

**Overall limitation**: no reduction achieves a uniform poly(n, log q) bound; several depend polynomially on q itself, and LIP-related reductions are restricted to prime fields — both flagged as open problems.

## 5. Solvers and Current Complexity Bounds

### PEP solvers

| Algorithm | Complexity | Remarks |
|---|---|---|
| Brute force | 2^(k log n + o(k log²n)) | Guess σ on an information set |
| Via Graph Isomorphism | 2^(n+o(n+q)) | Babai's algorithm per information set |
| Meet-in-the-middle variant | 2^(n/2+o(n+q)) | Probabilistic, randomized |
| Algebraic (Gröbner basis) | 2^(n log(k(n-k)/n²)+o(...)) | Heuristic |
| SSA (Support Splitting Algorithm) | O(n³ + q^h n² log n) | h = hull dimension; heuristic |

### LEP solvers

| Algorithm | Complexity | Remarks |
|---|---|---|
| Brute force | 2^(k log n + o(k log²n)) | Guess σ, then solve diagonal |
| Via Graph Isomorphism | 2^(2(q-1)n+o(n)) | Babai's algorithm on the code closure |
| Meet-in-the-middle variant | 2^(n/2+o(n+q)) | Probabilistic |
| Leon's algorithm | O(log(N_w)·C_ISD) | ISD-based |
| Beullens' algorithm | O(√(n log n / N_w)·C_ISD) | ISD-based, uses multiset collisions |
| Nowakowski's algorithm | 2^(n/2·H(k/n)+o(n)) | Randomized, requires q ≥ 7 |
| SSA extension | O(n³ + q^k n² log n) | SSA applied to the code's closure |

Where N_w = number of codewords of weight w, C_ISD = cost of an Information Set Decoding routine, H = binary entropy function.

**Key asymmetry**: PEP has multiple known classes of weak (often average-case polynomial) instances (via hull properties, SSA, Schur products). LEP has almost no broad weak-instance classes over large fields — only small-field special cases and small-dimension cases — making generic large-field LEP the more credible hardness assumption for cryptography.

### Solver families in brief

- **Algebraic (Saeed)**: reduces equivalence to a linear system GMH'^T = 0 over monomial matrices M; the open difficulty is encoding "M is monomial" as linear constraints.
- **Combinatorial / codeword search (Leon, Beullens)**: build invariant-preserving subsets of low-weight codewords and match them; bottlenecked by NP-hard low-weight-codeword search (via ISD).
- **SSA (Sendrier)**: punctures the code repeatedly and matches hull weight-distributions; runtime exponential only in hull dimension — very effective on generic instances, weakest against self-orthogonal codes.
- **Power/Schur-code solvers (Battagliola et al.)**: raise codes to a power to force diagonal scalars to cancel algebraically; yields new classes of easy LEP instances, especially for small-rate codes — the first attack exploiting field-algebraic structure directly.
- **Canonical forms (Chou–Persichetti–Santini; Nowakowski; Bennett et al.)**: associate a canonical representative per equivalence class via Left-Right-Linear equivalence; success probability improved from exponentially small (constant q) to 1 − O(n⁻¹) for q ≥ 7; further asymptotic and quantum (Grover/BHT-based) variants exist.
- **Side-information solvers**: given pairs of corresponding codewords (from low-weight-codeword leakage), recovery has improved from Ω(log n) pairs down to as few as a single pair; reuse of the same secret monomial across instances also enables partial recovery via linear constraints — a cryptographic reuse risk.

## 6. Open Problems Highlighted

- Find an efficient, characterizing invariant for code equivalence.
- Prove a search-to-decision reduction for LEP (only known for PEP).
- Achieve uniformly poly(n, log q) reductions across all known problem links.
- Extend LIP reductions beyond prime fields.
- Determine whether random codes have automorphism group {λ·id} with high probability for q > 2 (proven only conjectured).
- Exploit connections to matroid isomorphism and projective systems — linearly equivalent codes give isomorphic matroids and equivalent projective systems, but algorithmic consequences remain unexplored.
- Clarify what side-channel leakage on the secret monomial transformation implies for solver cost.
- Reconcile the fact (Carlet et al.) that every code over F_q, q>3, is linearly equivalent to an LCD code — this cannot currently be composed with the closure-based PEP reduction without reintroducing linear (not permutation) equivalence.

## 7. Bottom Line

PEP is comparatively well understood: reducible to graph isomorphism under trivial hull, solvable in average-case polynomial time for most random instances via SSA, with genuinely hard instances isolated to the self-orthogonal case. LEP, especially over large fields (q ≥ 4), remains far less understood — no broad weak-instance class is known, existing reductions to easier problems are lossy or field-restricted, and the best solvers still carry exponential worst-case cost. This asymmetry is precisely why the field currently treats large-field LEP as the more trustworthy cryptographic hardness assumption, while the survey's open-problem list aims to either find hidden weaknesses in it or place its hardness on firmer theoretical footing.
